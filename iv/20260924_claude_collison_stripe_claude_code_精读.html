代理式开发的可靠性保障、研发效率与代理商务展望——Stripe联合创始人兼首席执行官Patrick Collison访谈要点梳理（Claude 官方频道，2026-09-24）

Claude 官方频道，Stripe CEO Patrick Collison 与 Anthropic 一方主持人 Boris 对谈，18 分钟 · 2026-09-24

——据Claude 官方频道节目《Patrick Collison on Claude Code at Stripe》（2026-09-24）整理

摘要：本文对Claude官方频道节目中Stripe联合创始人兼首席执行官Patrick Collison与Anthropic的Boris对谈的主要观点进行了梳理汇总。梳理了Stripe在高可靠性约束下推行代理式开发的流程与护栏体系，介绍了代理式开发对可靠性、研发效率和工作方式的影响，以及Stripe平台观察到的创业生态变化，最后阐述了Stripe面向代理间交易的产品规划。据其介绍，Stripe约55%的代码合并请求（PR）以一句提示发起，Stripe Projects的开发提速约6倍，过去一年平台新企业创设速度约翻一倍。

关键词：编程代理；研发效率；代理安全；企业采用；代理商务；Stripe；Claude Code

一、高可靠性约束下的开发体系与护栏建设

针对Stripe为何能够将开发流程迁移至远程虚拟机，Collison将其归结为对端到端开发与质量保证流程的整体投入，以及多年积累的护栏基础设施。

（一）可靠性与部署速度兼顾的开发流程

Collison指出，金融服务业的软件通常一个月、一个季度，部分机构甚至半年才部署一次，这种做法换来了局部的稳定，但也付出两方面代价：一是无法及时获得客户的快速反馈；二是每次迁移都积压了数月的改动，使发布过程变得“极其可怕”。

Stripe的核心API需达到五个半九的可靠性，同时又要持续部署、一天之内多次获取客户反馈，两方面要求均不愿让步。基于此，Stripe对端到端的开发与质量保证流程进行了整体投资：一是以开发盒（devbox）作为链条的第一环；二是在开发盒之上配置观测、埋点与运维功能；三是在后端衔接渐进发布，先部署至少数几台机器，再扩大至1%的机器，逐步放量。他认为，要同时满足极致的可靠与安全以及极致的速度，只能依靠这样一整套体系。

（二）Minions编排工具与Claude Code的部署

在上述基础上，Stripe开发了名为Minions的编排工具。据其介绍，工程师可通过Slack、网页界面或原则上任何工具中的一句提示下达任务，系统随即为该任务新建一台虚拟机，由代理在其中完成打包、提交、构建、运行测试套件等全部步骤。目前Stripe约55%的PR以一句向Minions下达的提示发起。与此同时，每台开发盒均预装Claude Code，按Collison的说法，这是“中位数的人完成任务时第一个去的地方”。

（三）以不变量和硬边界为核心的护栏

主持人提及Anthropic一侧提供的对齐、提示注入防护等保护措施。Collison则强调，Stripe的护栏主要依靠不变量与硬边界，较少依赖主观、自由裁量或概率性的机制。他表示，模型对齐程度提高、更可能写出正确或安全的代码固然有益，但“没有什么是完美的”，真正需要依赖的是保证。

主持人认为，在AI出现之前将约束编码为基础设施有两方面好处：一是减少工程师犯错；二是通过数据隔离使人员“字面上访问不到不该访问的数据”，这些投入在代理时代带来了红利。Collison表示认同，并介绍Stripe自2017年起系统投资这套体系：一是围绕数据建立标签与语义感知的护栏；二是多年来完成了大量数据标注与细粒度授权；三是投入初衷在于安全保证至关重要，结果“有点意外地”使公司在代理式开发到来时处于更有利的位置。

值得注意的是，Collison还提出，AI与大模型对攻防哪一方更有利仍是悬而未决的问题，他预计几年后形成的均衡“会明显偏向防守方”。

二、代理式开发的可靠性表现与研发效率

Collison认为，在Stripe的实践中，开发速度大幅提升的同时总体可靠性保持稳定，节省出的产能分别投向新产品与架构改善。

（一）可靠性表现

Collison承认，业内普遍担心代码写得快了就难以逐行审阅，AI对可靠性的影响方向尚无定论。据其介绍，一位Stripe工程师上半年合并了600多个PR，全部由AI编写，其中仅有一个被回滚，这至少说明“开发速度大幅提升与经验上相当高的可靠性可以并存”。

从更系统的数据看，过去18个月呈现三方面变化：一是单个PR的质量在上升；二是单位时间的事故数略有上升，多为小型事故；三是各类二级兜底机制在问题扩散前将其拦截，总体可靠性“基本不变”。他将这一结果称为“相当令人振奋”，并进一步判断，大模型使此前无法构建的观测、埋点、harness与自动审查成为可能，“未来一两年AI净效果会让Stripe可靠得多”。

（二）Stripe Projects案例

Collison以Stripe Projects为例说明研发提速的幅度。该产品构想源于Claude Code的使用体验：用Claude Code开发任何具有一定分量的项目，都需要接入一组外部服务，例如日志使用PostHog、托管使用Vercel，另需一个数据库，而这些服务商几乎都已是Stripe的客户。基于此，Stripe与其合作，以新的方式开放相关能力，使代理可以十分便捷地在这些服务上开户。

据其介绍，该项目年初形成构想，从构想到公开发布由两到三名工程师用时约两个月完成，工作内容包括两方面：一是内部API、服务与harness；二是接入目前约50家各有特殊情况与偶发缺陷的第三方服务。他表示，“在从前的时代”两三个人八周做不成这件事。

对于以往条件下所需的时间，一位参与项目的工程师估计需要“更大的团队、六个月”。Collison按“团队翻倍、时间三倍”粗略测算，提速约6倍，并补充两点：一是工程师估算工期“出了名地乐观”，6倍可能仍属低估；二是Stripe拥有数千名工程师，未必每个项目都能达到这一量级，提速幅度应呈分布状态，有的项目快得多，有的则变化不大。他认为，“哪怕整体只有2倍，那也是大得离谱的一件事”。

（三）生产率的去向

对于工程师节省的时间投向何处，Collison表示更多项目与更多实验两方面均有体现，并可在数据中观察到。

一是新产品与新功能数量显著增加。Stripe刚刚举办年度大会Sessions，今年发布的新产品与新功能数量“远超以往任何一年”，工程组织规模虽有所扩大，但生产率效应明显在起作用。他同时指出，“功能”的颗粒度划分带有主观性，只是历年之间尽量保持口径一致。

二是更多资源投向架构与代码库改善项目，这一点与市场对“AI垃圾代码”的担忧方向相反。Stripe内部常引用一位朋友的说法，“每个代码库现在都是另一个代码库的提示”，前Stripe员工Jarred Sumner对Bun的重写即印证了这一点。对于三年后Stripe代码质量更高还是更低的问题，他的回答是“必须更高”。

主持人认为，token与基础设施之间存在流动性，token既可用于编写产品代码，也可用于编写基础设施和护栏，业界过度关注直接构建产品，而这些中间用途的作用往往更为关键。

三、内部采用进程与工作方式转变

Collison表示，Stripe内部对Claude Code的采用“非常热情、非常彻底、非常快”，主要难点在于持续更新对工作方式的认识。

他将相变点归结为两方面：一是Claude Code作为一种工作形态本身；二是去年底的模型能力提升。今年以来，人们真正需要转变的是对“什么是可能的、现在可以怎样工作”的认识。

据其介绍，一位Stripe同事的工作方式颇具代表性：一是先使用当时可获得的顶配模型，投入大量精力制定一份极为复杂、详尽的计划；二是派出十台开发盒，各运行一个代理执行计划的不同部分；三是代理可持续工作一整天，极端情况下持续数天。Collison指出，这与AI出现之前的工作方式完全不同，即便有了Claude Code也并不显而易见，原因在于“一次劳动的量子可以这么大”，前提是编排得当、模型能够进行大量自我验证。他坦言自己近期也低估了计划模式的价值，今年改变了使用模型的方式，难点在于对一个不断变化的形态持续重建直觉。

主持人表示，以往有大量开了头未完成的项目，现在“每个项目都会做完，然后再决定要不要”。Collison认为，“洗澡时的念头变成现实的比率高得多了，好奇心的回报变高了”。

四、支付平台视角下的创业生态变化

Collison认为，Stripe平台数据显示新企业创设明显加速，企业质量同步提升。

主持人介绍，其每季度在Y Combinator演讲，过去询问“谁在用Claude Code”时，举手人数从寥寥几人增至全场；现在改问“谁100%的代码用AI写”，在这些规模很小的初创公司中约七成举手，初创公司数量更多、速度更快、雄心更大。

（一）新企业创设速度

Collison以Stripe平台15年的企业创设时间序列作为生态代理指标，并以2020年3月的明显加速作为参照。据其介绍：一是过去一年的加速在相对幅度上“比以往任何一次加速都大得多”，单位时间在Stripe上启动的新企业数量“大约翻了一倍”；二是在覆盖度上，约四分之一的特拉华州公司经Stripe注册，未经Stripe注册的公司中有很多是跨国公司的零散子公司，因此在真正的初创公司中这一占比高于25%；三是这一加速在多数国家均可观察到。

（二）官方统计的滞后

Collison指出，很多情况下政府数据“还没醒过来”。Stripe经济学Substack专栏近期发文指出，英国官方公司统计显示新公司创设同比下降，而按照Stripe的方法论，英国正在经历创业的大幅激增。

（三）新企业质量

Collison更为看重质量方面的变化：一是新企业的平均收入在上升；二是按10万、100万或任一收入门槛划分，达标企业数量均大幅增加。他据此认为，当前“直截了当地是一个比不久前更好的创业时代”。针对AI可能带来更集中经济的担忧，他表示Stripe观察到的微观数据指向相反方向，即新企业更多、成功概率更高、整体增速在改善。

五、面向代理间交易的产品规划

Collison表示，AI正在改变Stripe自身的产品规划，团队设想的是一个“多数交易两端的对手方都是代理”的世界。

围绕各类代理和Claude Code实例如何直接使用Stripe、如何更广义地开展交易，团队重点思考以下问题：一是代理如何注册和使用Stripe；二是模型上下文协议（MCP）是否足够，Stripe命令行工具（CLI）应承担哪些功能，如何确保Stripe中的一切都能通过CLI或其他对代理可及的方式编排；三是代理之间如何相互付款、使用何种货币。主持人将其概括为“代理对代理的经济”。

Collison给出的“Stripe公司观点”是，三年左右多数交易将发生在代理之间，未必多数金额直接发生在代理之间，但“如果没有一个由相当小额的代理间支付构成的旋涡，我会很意外”。

总的看，Collison认为，Stripe依托持续部署体系和自2017年起建设的护栏基础设施，在总体可靠性基本不变的情况下大幅提升了研发效率，节省出的产能一方面投向新产品与新功能，另一方面投向架构与代码库改善；与此同时，Stripe平台数据显示新企业创设加速、质量提升，公司正围绕代理注册、CLI编排与代理间支付调整产品方向，并预计三年左右多数交易将发生在代理之间。
