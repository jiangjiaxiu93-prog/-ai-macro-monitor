Collison 称 Stripe 约 55% 的 PR 由一句提示发起、一名工程师上半年合并 600 多个 AI 写的 PR 只回滚一个，Stripe Projects 两三人八周上线对比“更大团队六个月”约合 6 倍提速，平台上新企业创设速度约翻倍、四分之一特拉华公司经 Stripe 注册，公司观点是三年内多数交易发生在代理之间（Claude 官方频道，2026-09-24）

Claude 官方频道，Stripe CEO Patrick Collison 与 Anthropic 一方主持人 Boris 对谈，18 分钟 · 2026-09-24

本文整理的是 Anthropic 在 Claude 官方频道发布的一段 18 分钟对谈，Stripe 联合创始人兼 CEO Patrick Collison 讲 Stripe 内部如何用 Claude Code 开发，主持人为 Anthropic 一方的 Boris。口径提示放在前面：这是模型厂商自家频道的客户案例视频，全部数字均为 Collison 口述或视频说明文字，无独立核实；“约 55% 的 PR 从一句给 Minions 的提示开始”这一数字出自视频说明，字幕里对应那句被转写吞掉了半句；6 倍提速是 Collison 自己用“两三人八周”对比一位工程师“更大团队、六个月”的估算，他本人也说“工程师估工期出了名地乐观”。本文只取投研相关线索：一家核心 API 要求五个半九可靠性的支付公司怎样把代理式开发跑到 PR 的一半以上、护栏为何要做成基础设施、少依赖模型对齐、生产率提升的量级与去向、Stripe 平台数据对创业生态的读数，以及 Stripe 对代理间支付的判断。中心判断是：Stripe 的案例把“可靠性与速度只能二选一”的行业默认打掉了一角，靠的是 2017 年起为安全合规铺的数据标注与权限体系在代理时代意外派上用场，而 Collison 给出的生态数字（新企业创设翻倍、单企业平均收入上升）是这一轮周期里少见的来自支付轨的下游需求实证（作者归纳）。

五个半九与持续部署：隔离开发盒和渐进发布是“同时拿到可靠与快”的唯一路径

主持人开场问，业内很多公司试过把开发搬到远程虚拟机上，Stripe 凭什么有信心做成。Collison 的回答从行业惯例讲起：金融服务业的软件通常一个月、一个季度、有些地方半年才部署一次，这给了“局部的稳定”，代价是两条，一是拿不到客户的快速反馈，二是每次迁移都积压了数月的改动，变得“极其可怕”。Stripe 的核心 API 要做到五个半九的可靠性，同时又要持续部署、一天里多次从客户那里拿反馈，两头都不肯让，于是只能把端到端的开发与质量保证流程整个投资一遍。开发盒（devbox）只是这条链的第一环，上面挂着观测、埋点与运维特征，后面接的是渐进发布，先上几台机器，再上 1% 的机器，逐步放量。他把结论说成一句话：需要极致的可靠与安全、又需要极致的速度，“这是同时达成两者的唯一办法”。

在这套基础上，Stripe 做了一层叫 Minions 的编排工具，用 Slack、网页界面或原则上任何工具里的一句提示就能下达任务，系统为这个任务新建一台虚拟机，代理在里面完成全部步骤，打包、提交、构建、跑测试套件，走完整个流程。视频说明文字给的数字是，Stripe 现在约 55% 的 PR 以一句给 Minions 的提示开始。

可靠性的实证：600 多个 AI 写的 PR 回滚一个，单 PR 质量 18 个月上升，事故数略增而总可靠性不变

主持人把 Stripe 称为行业可靠性的标尺，Collison 顺势回答了“AI 是顺风还是逆风”这个问题。他承认业内普遍担心写得快了就不会逐行审阅，方向未定，然后给了一个当天早上刚问到的样本：一位 Stripe 工程师上半年合并了 600 多个 PR，每一个都是用 AI 写的，其中恰好一个被回滚。他说这至少说明“开发速度大幅提升与经验上相当高的可靠性可以并存”。

更系统的读数是三条并列的曲线。过去 18 个月，单个 PR 的质量在上升；单位时间的事故数略有上升，多为很小的事故；所有二级兜底机制把问题在扩散前拦住，总体可靠性“基本不变”。他把这个结果称为“相当令人振奋”，并进一步判断，有了大模型之后可以造出以前造不出的观测、埋点、harness 与自动审查，所以“未来一两年 AI 净效果会让 Stripe 可靠得多”。

护栏做成基础设施：靠不变量与硬边界，少靠模型对齐，2017 年起的数据标注在代理时代“意外”兑现

主持人追问具体的护栏是什么，提到 Anthropic 一侧有对齐、提示注入防护等保护。Collison 的回答把重心放回 Stripe 自己这边：主要靠不变量与硬边界，少靠主观、自由裁量或概率性的东西。模型对齐、更可能写出正确或安全的代码当然好，但“没有什么是完美的”，真正要依赖的是保证。主持人把这归纳为 AI 之前把约束编码成基础设施的两个好处，工程师少犯错，以及数据隔离让人“字面上访问不到不该访问的数据”，如今这些在代理时代“派上了红利”。

Collison 完全同意，并补了时间线：Stripe 从 2017 年起认真投资这套装置，围绕数据做标签与语义感知的护栏，多年下来做了大量标注与细粒度授权，动机是安全保证太重要，结果“有点意外地”让公司在代理式开发到来时处在更好的位置。主持人接了一句“幸好 Claude 也擅长写护栏”。Collison 顺带给了一个更大的判断：AI 与大模型对攻防哪一方更有利是个悬而未决的问题，他猜几年后的均衡里“会明显偏向防守方”。

Stripe Projects 案例：两三名工程师约两个月接入约 50 家服务，对比估算约 6 倍提速

每台开发盒预装 Claude Code，是“中位数的人完成任务时第一个去的地方”。Collison 举的样本是 Stripe Projects。这个产品的想法本身来自 Claude Code 的使用体验：用 Claude Code 做任何有点分量的项目，都要接一组外部服务，日志用 PostHog、托管用 Vercel、再要一个数据库，这些公司几乎都已经是 Stripe 的客户，于是 Stripe 想到与它们合作，把能力以新的方式暴露出来，让代理可以极其容易地在这些服务上开户。年初有想法，决定去做，从第一个念头到公开发布，两到三名工程师约两个月，这不只是内部 API、服务与 harness，还包括接入现在约 50 家各有怪癖与偶发 bug 的第三方服务。他说“在从前的时代”两三个人八周做不成这件事。

主持人问从前要多久，Collison 说他问过一位参与的工程师，估计是“更大的团队、六个月”。他自己按“团队翻倍、时间三倍”粗算得到 6 倍，随即加了两层折扣：工程师估工期出了名地乐观，所以 6 倍可能还是低估；Stripe 有数千名工程师，未必每个项目都有这个量级，应该是一个分布，有的快得多有的不快。他把底线放在“哪怕整体只有 2 倍，那也是大得离谱的一件事”。

生产率去了哪里：新产品新功能远超往年，同时更多项目投向架构重构，“每个代码库都是另一个代码库的提示”

主持人问工程师省下的时间做什么，是更多项目还是更多实验。Collison 说两者都有，并且能在数据里看到：Stripe 刚开完年度大会 Sessions，今年发布的新产品与新功能数量“远超以往任何一年”，工程组织虽然大了一些，但显然有生产率效应在起作用。他强调“功能”的颗粒度是主观的，只是年与年之间尽量保持一致口径。

他认为更有意思、也与“AI 垃圾代码”担忧相反的一点是，Stripe 现在承接了更多改善架构与代码库的项目。Stripe 内部常引一位朋友的话，“每个代码库现在都是另一个代码库的提示”，前 Stripe 员工 Jarred Sumner 用 Bun 的重写证明过这一点。对“三年后 Stripe 代码质量更高还是更低”这个问题，他的答案是“必须更高”。主持人把这一段概括为 token 与基础设施之间的流动性：token 可以用来写产品代码，也可以写基础设施、写护栏，业界过度关注直接造产品，而这些中间用途才是最有力的部分。

采用的障碍：真正的相变是 Claude Code 这一形态与去年底的模型升级，难点在重建“一次能派多少活”的直觉

问到规模化过程中的障碍，Collison 先说采用“非常热情、非常彻底、非常快”，所以问障碍显得有点滑稽。他把相变点定在两处，Claude Code 作为一种工作形态本身，以及去年底的模型能力提升。今年以来人们真正要转过弯的是“什么是可能的、现在可以怎样工作”。他举了一位 Stripe 同事的工作方式：先用当时能拿到的顶配模型花大力气做一份极复杂、极详尽的计划，然后派出十台开发盒、各跑一个代理执行计划的不同部分，可能干一整天，极端情况下干好几天。这与 AI 之前的工作方式完全不同，而且即便有了 Claude Code 也并不显然，因为“一次劳动的量子可以这么大”，前提是编排得当、模型能做大量自我验证。Collison 说自己最近也低估了计划模式的价值，今年改变了用模型的方式，难点是对一个不断移动的形态持续重建直觉。主持人补了一个个人体验，以前有一大堆开了头没做完的项目，现在“每个项目都会做完，然后再决定要不要”，Collison 说“洗澡时的念头变成现实的比率高得多了，好奇心的回报变高了”。

支付轨上的下游读数：新企业创设速度约翻倍、四分之一特拉华公司经 Stripe 注册、单企业平均收入上升、英国官方统计尚未察觉

主持人说自己每季度去 Y Combinator 讲话，以前问“谁用 Claude Code”，从几只手到全场举手；现在改问“谁 100% 的代码用 AI 写”，在这些很小的初创公司里大约七成举手，初创公司更多、更快、更有野心，问 Stripe 的数据是否看到同样的事。Collison 给了 Stripe 平台 15 年的企业创设时间序列作为生态代理指标，并拿 2020 年 3 月那次明显加速做参照：过去一年的加速在相对幅度上“比以往任何一次加速都大得多”，单位时间在 Stripe 上启动的新企业数量“大约翻了一倍”。覆盖度上，约四分之一的特拉华公司经 Stripe 注册，未经 Stripe 注册的那些有很多是跨国公司的随机子公司，所以在真正的初创公司中占比还要高于 25%。

他说这一加速在多数国家都能看到，很多情况下政府数据“还没醒过来”。Stripe 经济学 Substack 最近发过一篇，英国官方公司统计显示新公司创设同比下降，而按 Stripe 的方法论，英国正在经历创业的大幅激增。更重要的是质量方向：新企业的平均收入在上升，按 10 万、100 万或任何收入门槛切分，达标企业数也都大幅增加。他的结论是现在“直截了当地是一个比不久前更好的创业时代”，并针对“AI 会带来更集中的经济”这一担忧说，Stripe 观察到的微观数据指向相反，新企业更多、成功概率更高、整体增速在改善。

产品方向：代理如何开户、CLI 能否承载全部操作、代理之间用什么货币结算，公司观点是三年内多数交易发生在代理之间

最后一问是 AI 有没有改变 Stripe 自己在造的产品。Collison 说团队在想所有代理与 Claude Code 实例会怎样直接使用 Stripe，以及更广义地怎样交易，设想的是一个“多数交易两端的对手方都是代理”的世界，具体问题包括代理怎样注册 Stripe、怎样使用 Stripe、MCP 够不够、Stripe CLI 该做什么、怎样确保 Stripe 里的一切都能从 CLI 或其他对代理可及的方式编排，以及代理之间怎样互相付款、用什么货币。主持人把它概括为“不只是代理经济，是代理对代理的经济”。Collison 给出的“Stripe 公司观点”是，三年左右多数交易将发生在代理之间，未必多数金额直接发生在代理之间，但“如果没有一个由相当小额的代理间支付构成的旋涡，我会很意外”。

投研视角的几点归纳（作者归纳）

第一，这是本轮周期里少见的“高可靠性要求场景”下的代理式开发定量样本。此前的同类数字多来自 Shopify（约一半代码变更请求由 AI 同事 River 生成）与初创公司，Stripe 的特殊之处在于五个半九的 API 可靠性约束，Collison 给出的三条曲线（单 PR 质量升、事故数略升、总可靠性不变）比“PR 占比”本身更有信息量，因为它承认了代价，且把代价归到了兜底机制的负担上。第二，护栏与数据权限做成基础设施是前置条件，这项投入从 2017 年开始，意味着大企业复制 Stripe 路径的瓶颈在多年的数据标注与授权体系，与模型选择关系不大，这与 Ghodsi、Levie 近期反复强调的“企业扩散慢在流程与上下文”一致。第三，生产率的去向有一部分流向架构重构，未全数流向新功能，这一点会削弱“代码总量膨胀即技术债膨胀”的推断，也是 token 需求里“非面向用户的后台消耗”的又一例证。第四，Stripe 平台的新企业创设翻倍与单企业平均收入上升，是来自支付轨、覆盖约四分之一特拉华公司的下游需求读数，与 Collison 在 5 月 Replit 对谈中的口径一致但幅度更新，可作为“应用层繁荣是否真实”的一项外部证据；它同时说明官方统计存在滞后，用政府数据判断创业周期会低估当前节奏。第五，Stripe 把代理间小额支付定为三年内的公司观点，与 7 月 Emily Sands 所说“支付轨已部署而代理间交易尚未发生”相比，时间表被明确压缩到三年，这是支付基础设施方对代理商务节奏的最新表态。
