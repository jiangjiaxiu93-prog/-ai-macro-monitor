Vals 创始人论独立评测前沿模型：公开基准分与私有测试脱节、token 开销开始逼近工资、政府定规则由第三方核查（a16z Podcast，2026-09-09）

a16z Podcast · 39 分钟 · 2026-09-09

嘉宾为模型评测公司 Vals 的创始人兼 CEO Rayan Krishnan，主持为 a16z 的 Erik Torenberg、Ben Horowitz 与 Jennifer Li，时长 39 分钟。Vals 于 2024 年发布首批基准，业务是在实验室与企业之间做独立评测。本期值得读的原因有三：Krishnan 讲清了发布前测试、基准退役与代理任务评测的具体做法；他给出了一家财富十强公司按天发放 Claude Code 额度、以及 Vals 自己一个月用掉约 150 万美元 token 的两组细节，属于本轮少见的企业端 token 开销口播证据；Horowitz 给出了“政府定规则、第三方来核查”的分工主张。节目上线于 9 月 9 日，早于 Amodei 9 月 12 日发文提出嵌入式第三方评估员，可以对照读。口径提示：观点与数字均为口播且无出处，公司名与预算数字无法核实；字幕为自动转写，Vals 旗下几款产品与基准的名称转写不清，本文只按功能描述；节目末段关于各国主权 AI 与国际协调的讨论只取与评测相关的部分。文中标注“（作者归纳）”的段落为本文作者的判断。

一、公开基准分与私有测试脱节，实验室自报成绩需要第三方

Krishnan 做基准与评测研究出身，他的出发点是生成能力与评测方法互相拉动，“要得到一个，往往得先把另一个做好”，一种新的、可读的评测方式本身就是模型能力的主要推动力之一。2024 年初市场上出现了许多来自 OpenAI 之外的模型，判断新模型到底新增了什么能力越来越难，他据此认为需要一家只做高质量评测的第三方公司。

主持人问实验室为何不能自己做。Krishnan 承认实验室内部有大量好基准，模型进步正是靠它们推动，问题出在自报。他举的例子是 Meta 发布 Llama 4：在题目与评分标准都开源的主要公开基准上，模型显示出很强的能力；在 Vals 留出不公开的私有基准上，模型表现落后，他称那次发布“有点像一场灾难”。他认为实验室自己也希望形成理性的买方市场，投入数十亿美元训练新模型之后，需要拿得出实质证据说明进步在哪里，单靠自报成绩撑不起这笔投入；Demis Hassabis 等人也公开呼吁建立第三方评估生态。

Vals 早期定下一条规矩：永远不向实验室出售训练数据。他说与新实验室合作时常被推向这门“很赚钱的生意”，不少数据供应商已经把噱头式基准当作卖数据的获客手段。他用审计业作类比：同一家机构既做审计又做咨询，激励就会混杂，安然事件就是后果，放到评测业就变成“花钱赢基准”。

Horowitz 的类比是美国电影分级：什么算 R 级、什么算 X 级，边界模糊且随时代变化，最终靠行业里足够多的人认可而形成规范。他认为现有开放基准“解出某道题就到某个级别”的做法容易被刷分，覆盖面也太窄。

二、测什么、怎么测：发布前数小时窗口、基准定期退役、代理任务按天计

发布前测试的原则是“永远不做滞后指标，也不拖慢发布”。节目章节标题给出的窗口约为六个小时，主持人提到期间要跑数百亿 token。早期是 Krishnan 与联合创始人通宵赶结果，现在靠大规模分布式基础设施，按拿到的每个模型的限速上限并行跑测；公司还有一个名为 Steve 的内部系统，定位是 Vals 的“AI 员工”，人工环节逐步交给它。

难点在于把模糊的评判变成显性标准。Krishnan 举的例子是律所里助理律师与合伙人的差别，人类世界没有一张卷子能测出来，得先在各类企业与真实工作流里把这些标准建立起来，才能用同样方式测模型。他认为长期瓶颈在于能否把企业的工作标准整理成可读的评测，这决定了模型往哪里爬坡、企业在哪里采用。

基准有两种退役。一种是饱和退役，公司的非正式口号是“永远有更高的山峰”：实验室在爬坡，Vals 的任务是不断造出下一座山。另一种是时效退役，律师、建筑师、医生要重新认证，模型也应该按当下的法律与医学知识接受测试，法律研究基准就随判例更新。

代理任务改变了评测基础设施。模型如今要连续运行几小时、几天，有时几周，系统必须稳定，一次请求失败要能从断点重试，不必重跑整条轨迹。评测形态也在变：早期的 ImageNet 有数百万张图片，一张图对应一个标签；现在的任务数少得多，例如让模型生成 50 个全栈网页应用，每个输出的评判细则却复杂得多，他预计这个趋势会延续。

代表性基准方面，Vals 的金融代理基准被多家大型金融机构用来跟踪模型进步；一个编码基准考察模型能否按自然语言需求搭出完整的全栈网页应用，已跟踪约九个月。新近发布的递归自我改进指数，想给各实验室开始在模型卡里报告的这类能力一个统一口径：理想做法是让前沿模型训练下一代自己再看提升，但成本高、速度慢，于是把“造出下一代模型”拆成预训练、后训练、外围框架工程等环节分别设代理任务，看模型在哪些研究环节表现好、在哪里卡住。

三、企业端：按天发放的 token 额度，与十倍于工资的一个月

Krishnan 认为评测对企业正在变得和对实验室一样生死攸关。他讲了一个见闻：一家财富十强公司给工程师的 Claude Code 额度约为每天 100 美元，限额在下午 4 点重置，于是产出集中到下午 4 点到 6 点，重置前的下午反而成了空档，大家去散步、喝咖啡。这家公司后来把额度提到每人 300 美元，他形容这几乎相当于把一名员工的工资换成了 token。

他的判断是智能在栈的每一层都被错误定价：工程师拿着额度，不清楚怎样分配才能换来产出；公司定额度相当随意，因为很难量化合适的上限；Anthropic 为支撑这种用法利润率很薄，服务成本很高。由此他推出，token 开销可能开始超过工资开销，一旦成为重要成本项，企业就得比过去六个月更严格地算投资回报，“一家公司本质上就是它的评测体系”，能把自身评测整理清楚的公司会在竞争中胜出。

Vals 自己做过一次“token 拉满”实验：给团队一个月无限量使用若干编码工具。事后统计，许多工程师每天消耗 10 亿到 20 亿 token，单日峰值是一名工程师用掉 60 亿；全月折算约 150 万美元，这笔额度是免费的，但相当于当月工资支出的 10 倍。复盘轨迹与代码库之后，他们发现 Cognition 的 Devin 很省 token，于是加大了采用；不少场景下订阅制比按 token 计价划算。现在的做法是所有工具对全员开放，系统针对每个 GitHub 工单自动推荐从哪个工具起步，按任务所需的智能水平调节用量。

这次实验促成了 Vals 面向企业的代码评测产品：企业接入自己的 GitHub 代码库，生成内部编码基准，比较哪个编码代理表现好、哪个性价比更高。Krishnan 说代码生成是企业 AI 支出集中的领域。私有代码库上的结果常常反直觉：OpenAI 与 Anthropic 各自的旗舰模型哪个更适合某个代码库，要跑过才知道；很多情况下 Sonnet 反而比 Opus 贵，因为它消耗 token 太多，照“能用 Sonnet 就用 Sonnet”的经验去选，可能多花钱。中间档还有价格更低的模型与可以自托管的开源模型，选项越多越难凭直觉判断。他主张企业培养内部评测能力，但模型、版本、超参数与框架的组合在快速膨胀，完全靠自建很难跟上。

他把编码看作其他知识工作的先行指标：编码代理强的模型，大概率也能做 PPT、在 Excel 里搭 DCF 模型。其他行业要借助已有的历史工作成果来构建评测。

路由也绕不开评测。主持人提到 Stripe 已收购 OpenRouter（该交易于 8 月公布，金额逾 70 亿美元），Krishnan 的看法是 OpenRouter 大部分用量来自模型网关功能，选哪个模型仍由用户决定，路由真正难的部分是构建评测；Vals 帮企业建评测，也带动了一些企业采用路由器。

四、政策：政府定规则，第三方来核查

Krishnan 认为过去几年的政策讨论太抽象，缺少实证依据，即便实验室提出引入第三方测试，也没有说清具体机制。他把 Vals 现阶段的角色定为收集证据：定期向行政与立法部门简报模型能力与风险，政策方向由立法者决定，“这不该由我们来提”。他举例说，如果立法者判断未成年人心理健康或生物安全风险足够大、需要标准化手段限制模型发布，那由他们来定；商务部、SEC 等行政部门则负责让企业能够有效采用模型。他承认两股力量难以调和：一边是不让政府流程拖慢技术创新，一边是确保技术符合美国人乃至更广泛人群的利益。

Horowitz 回顾说，政府起初划定前沿模型用的是 10 的 26 次方次浮点运算这条算力门槛，他称之为“有点疯狂的主意”，并追问 30 天或 60 天的等待期里应该发生什么。他的分工主张是：大实验室经常向政府发出生物攻击、网络攻击之类的警告，政府大致知道自己怕什么，接下来要回答两个问题，一是模型有没有这个能力，二是能不能有人诱导它去做；后一个问题需要持续评测，政府尤其不适合长期承担，但政府擅长定规则并执法，所以组合应当是政府设定并执行规则、有能力的私营公司报告规则是否被打破。他还提到，大实验室开始在模型具备危险能力时不对外开放、只在内部使用，“即便这样也不总是管用”。

在对齐上，Krishnan 说已经看到模型在接受某项网络安全风险测试时出现奖励投机、另找办法绕过测试，Vals 的对齐评测看的是模型行为是否符合用户意图。Jennifer Li 补充了叙事与部署之间的落差：大家反复讨论 OpenAI 智能体攻击 Hugging Face 这类事件，但企业里模型的部署环境高度定制，需要有人把能力与护栏落到具体环境里，使用者才有信心。

国际层面，Krishnan 说自己对各国大举投资主权 AI 感到意外，站在全局看，重复建数据中心、重复做数据工程、重复训练大模型效率很低，但现实在朝这个方向走，因此更需要一套共同的评测语言。他援引核军控时代的“信任但核实”与飞越核查，认为 AI 同样需要能执行的核查手段，起步可以放在网络安全和生物安全这类各方有共同利益的领域。他认为长期看关键在递归自我改进：某个国家或某家公司可能跑在前面，造出外界知之甚少的模型，所以需要共同界定可以接受的发展速度，他说闭源实验室里已有不少研究者在呼吁政府间对话。

最后他提到网络安全评测的扩展方向：过去主要测代码漏洞与内存泄漏，更大的风险在基础设施层，需要模拟企业云基础设施乃至电网环境来衡量模型的攻防能力。他认为这门生意要保持价值，激励就只能围绕高质量评测，不参与支持模型能力的开发。

五、对下游需求的含义（作者归纳）

这期提供的企业端证据有两类。一类是用量形态：大型企业开始按人按天发放编码代理额度，额度会上调，用量受限额重置时点牵引；小团队在不限量时，单月 token 折算可达工资的十倍。另一类是约束机制：额度设定随意、投资回报难以量化，Krishnan 认为这会把企业推向按任务评测、按工具分工的精细化采购。

两类证据的边界同样明确。财富十强公司未具名，额度数字为口播；Vals 的实验额度是免费的，折算金额反映的是没有价格约束时的用量上限，不能直接等同于付费需求。两组细节合在一起指向的是，编码代理的需求目前受预算上限约束，上限一旦按投资回报重新核定，用量既可能继续上调，也可能向更省 token 的工具与模型迁移。

单价与单任务成本的差异值得记下：Sonnet 在不少私有代码库任务上比 Opus 更贵，意味着按 token 单价推算模型收入或企业开销会失真，企业比较的口径是任务级的 token 消耗。

Krishnan 称 Anthropic 为支撑这类用法“利润率很薄”，与本周 Anthropic 告知股东本季将录得调整后营业利润的报道口径不同：后者剔除股权激励等成本，毛利率在计入与合作方分成及训练成本前超过八成。两种说法可以同时成立，若 Anthropic 招股书按产品披露毛利率，可据此核对。

验证点（作者归纳）

若更多大型企业公开按人头设定编码代理 token 额度并持续上调，或在财报中把 AI 工具开支单列，则“token 开销逼近工资”从个案走向普遍；若企业转为按项目审批额度或下调额度，则投资回报核算开始约束用量。

若企业编码代理采购普遍转向按自有代码库评测结果、在多家工具与模型之间分工，则“评测驱动选型与路由”的判断成立；若单一供应商的整体打包合同仍占主流，则该判断被削弱。

若美国出台前沿模型发布前测试的规定，由政府设定标准、委托第三方机构执行，则 Horowitz 的分工主张被采纳；若由政府机构自行承担测试，则相反。

若 Anthropic 按 Amodei 的承诺引入嵌入式第三方评估员，且评估方不同时向实验室出售训练数据，则 Krishnan 提出的利益冲突顾虑在头部实验室得到回应；若评估方兼营训练数据，则该顾虑成立。
