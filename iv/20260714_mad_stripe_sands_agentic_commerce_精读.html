Stripe 的 Emily Sands 论代理商务：支付轨已经部署而代理之间的交易还没发生、SaaS 零边际成本的前提被推理成本打穿、六分之一的 AI 注册是为了偷 token（The MAD Podcast，2026-07-14）

The MAD Podcast with Matt Turck · 75 分钟 · 2026-07-14

嘉宾为 Stripe 的数据与 AI 负责人 Emily Sands，经济学背景。这是她与该节目的第二次对谈，上一次在约一年前。对应用层专题的价值有三处：她是支付基础设施一侧的一手叙述者，讲的是已经上线的协议与原语；她把代理商务（agentic commerce，指发现、授权与支付由 AI 代理完成的商务形态）拆成自主性分级，并指出消费者侧当下停在哪一格；她给出一组只有支付网络才看得到的运营数字，其中 token 盗窃那一段把应用层的毛利风险讲成了可分类、可拦截的具体问题。

口径提示：全片数字均为嘉宾口播，节目未给书面出处，引用前需回原始口径核对，涉及 Link 的 3 亿用户、流经 Stripe 的约 2% 全球 GDP、AI 公司注册中超过六分之一属于滥用、免费试用滥用半年翻一倍多、Lovable 有 58% 交易量走 Link、Stripe 文档的代理流量占比约 40%、命令行工具 API 资源请求 70% 来自代理、2026 年批次 Atlas 初创同月份收入朝上一批的 5 倍走、新企业注册荷兰涨约 40% 芬兰 70% 法国 80%。本文基于自动字幕整理，专名按上下文还原。

一、已部署的与还没发生的：这是全片的主轴

她对过去十二个月的总结是从假设走到实物。一年前谈代理作为买方“是以相当假设性的方式在谈”，标杆体验还没定义下来，双方基本在从第一性原理推理；一年之后已经有实际部署的基础设施、有真实公司建在上面、有真实模式可学。

她给的框架是一条自主性光谱，并确认存在类似自动驾驶的分级。一端是机器支付协议所处的位置，代理自主发现服务、自行决定购买、完全自行处理交易，没有人在环里；另一端是人在某个 AI 界面里问“适合平足跑者的跑鞋”，AI 给出答案并越来越带一个购买按钮。消费者侧目前大体停在 L2，人们委托掉一点选择、或重度依赖 AI 找商品，“我们还不在用一个大语言模型一次性搞定暑期度假预订的世界里”。

已落地的合作她点了名：与 Google 合作让商户在 AI mode 与 Gemini 应用里直接销售，与微软和 OpenAI 在 Copilot 与 ChatGPT 里做同类的事。Meta 这条线她说风味略有不同，Stripe 在那里驱动的是广告内部的结账，随后补了一句延伸判断，“也许广告本身也在变成代理式购买”。

二、两个支付原语：共享支付令牌与 Link 代理钱包

代理商务协议与 OpenAI 共建，解决企业如何把目录、库存与价格暴露给代理。她在这里给了一个关键区分：库存是那种你希望被确定性地知道的东西，因此体验要演进到有一个正确的库存集合可供读取、以及其上正确的确定性元数据，大语言模型才能在这层确定性之上去做非确定性的事。第二个设计目标是避免重复注册，企业把目录暴露一次，即可选择性接入所有支持该协议的代理，理由是企业不愿只在一个代理界面上押注。

共享支付令牌是约六个月前专为代理商务而建的新支付原语。令牌里编码了代理被允许做什么：哪些商户可以被收费、金额上限、币种、有效期；代理在结账时出示令牌，从不看到底层凭证，覆盖范围不限于卡，包含先买后付这类选项。她强调协议与令牌都是平台无关、支付处理商无关，令牌可以转交给任何其他支付服务商。

它替换掉的前代方案是一次性虚拟卡，源头是平台与市场场景里司机代付的做法。她说代理商务第一个有意义的实盘交易量出现在 Perplexity 的购物上，但那个范围按定义是一次性的、通常限定单一提供商与固定金额。Link 是 Stripe 的消费者钱包，正在被做成代理钱包，灵活度高得多：可以设跨一组提供商的预算，可以在单笔层面授权，也可以只在超过某个金额时才要求授权，可以限制商户类别、限定只能从某家买或只能在某国买。她对时点留了余地，认为还要几个月消费者才会真正同意代理在特定范围之外使用钱包，而基础设施先就位，等消费者准备好时技术已经在线。

三、责任分配是她明确留白的地方

第一条设计原则是企业必须继续是记录商户，Stripe 把自己的工作理解为让代理式交易的行为方式与人类交易一致；她补了一个限定，这并不意味着代理需要受到与人类相同的约束，这是从企业视角说的。

第二条是护栏与控制要可编程且细粒度，收紧或放开都不应该要求更换钱包、支付轨道或目录暴露方式。企业那一侧的关键是关于底层买家、以及代表该买家行动的那个代理的好坏信息，要被完整传给企业。Radar 这个反欺诈产品因此从交易欺诈扩到各类欺诈与滥用，每一张共享支付令牌开箱包含 Radar 分数，同时回答两个问题：这是一个合法的买家吗，这个代理是在以合法的方式代表这个买家行动吗。

主持人提出这套推演到头还是要走进法院，如果出了严重差错、尤其是大额商务交易，究竟谁有过错，会不会追到底层的模型提供商。她没有给出责任分配规则，把范围扩到信任需要靠重复次数建立这个层面。这是全片留白最明显的一处，也是企业采购最需要答案的一处（作者归纳）。

四、SaaS 零边际成本的前提消失，混合计费成为通用解

过去十余年的 SaaS 变现经济学她形容为“相当漂亮而且简单”：产品建一次，多来一个客户几乎不花钱，边际成本近乎零，这是高毛利与固定费订阅或按座位许可好用的原因。如今每一个提示词、每一次 API 调用、每一个任务都有真实边际成本，因为推理不是免费的，客户如何使用产品直接决定企业赚钱还是亏钱。

她给的两个样本路径一致。Lovable 与 ElevenLabs 都从简单订阅起步，理由是早期、想快点变现、订阅对非技术消费者熟悉；随成本上升转向混合计费，落点是每月 25 美元或 100 美元档位对应一定 credits，超出阈值后按用量精确计费。她的观察是很少还有在扩张的 AI 公司纯粹只靠订阅或按座位收费。

代理成为买家后还要再走一步。她指出即便已经在做用量计费，月末才收费的话，到月末时一个代理可能已经花掉一个离谱的量。对应的产品组合是 Metronome 做实时计量、Tempo 做稳定币即时结算，在 token 被消耗的同时就把钱收上来，他们称之为流式支付。她把企业当下的处境描述为两难：把自助通路掐掉会很安全但增长很慢，开放给代理则暴露在滥用与货币损失风险下。

五、Token 盗窃：应用层毛利的一个新漏损

这是报告框架里没有位置的一条。机制是欺诈者不必去偷钱或偷凭证，可以直接偷 token；由于边际成本已经不为零，只要欺诈率足够高，产品的经济学会很快崩掉，她把这个风险称为存亡级。

三种模式她都给了量。多账户滥用规模让她自己看数据时都感到震惊，AI 公司的注册里超过六分之一属于这类滥用。免费试用滥用在 Stripe 上过去六个月里翻了一倍多，这次翻倍的大部分来自 AI 企业。用量计费下的欠款跑单是堆起数千美元成本、月末被开票、然后从不付款。被偷的 token 去向包括折价转售、批量生成音乐收版税，以及直接氛围编码出一个网站，后端把从被偷服务拿到的东西原样吐出来，当成自己的产品更便宜地卖掉。

她的判断是行业整体还没推理出这一点：正在发生的多数欺诈属于历史上会被称为第一方滥用的那一类，也就是转售滥用、账户共享、多账户与免费试用这些。Radar 的对策是把干预点前移到登录、免费试用开始与用量积累三个时刻，各给一个可拦截的分数。她提到六到九个月前还有 AI 公司说要靠取消免费试用或只打企业客户来解决，今天这类说法听得少了。

六、两组结构性数字：氛围部署与企业形成

第一组关于瓶颈位置的移动。Stripe 文档的代理流量一年涨了超过 10 倍，现在约占全部文档流量的 40%；命令行工具的 API 资源请求有 70% 来自代理。她的解释是长杆变了：以前难的部分在编码，现在应用二十分钟就能编出来，把它部署上去成了更紧的约束，她称之为氛围部署。她给这件事的经济含义是移除部署摩擦直接扩大了互联网经济，因为造得出但部署不了就卖不出去。

第二组关于企业形成。用 Stripe 自己的镜头看，新企业推出的速度自一年前那次对谈以来翻了一倍，2026 年批次的 Atlas 初创在相同月份数上的收入正朝着上一批次的 5 倍走，新企业注册在荷兰涨约 40%、芬兰 70%、法国 80%。她强调的构成是增量增长完全来自人口普查局用语里的非雇主企业，也就是独立经营者。老模式是先做大再全球化，现在是上线那天就在几十个国家，通过全球化来做大。

她对生产率的口径很谨慎：在全球数字里她认为看到了一些来自 AI 的生产率，但目前它主要还不来自消费，因为那些数字仍然很小，目前主要是在向经济里灌入一大堆 AI 资本开支。她对未来十二个月想看的东西是“代理作为一家微型公司”，在买、在卖、在配置基础设施、端到端地做完整件事。她同时给了当下的事实口径：今天代理对代理的交易并不多，这一块仍然在未来。

与《应用是如何诞生的？》的对应关系（作者归纳）

报告说 Muse 的支付环节与第三方支付企业合作，这期给了这条判断背后的基础设施事实。本期录制于 Muse 发布之前，她全程没有提 Muse，不能用来印证 Muse 本身；但 Stripe 在 Meta 这条线上驱动的正是广告内部的结账，并且同一套东西覆盖 Google、微软、OpenAI 几条界面。协议与令牌被设计成平台无关与支付处理商无关，意味着这个组合可以复制到任意新的代理界面。

报告上行情景里的代理间支付成熟，可以从“需要成熟”改写成“轨道已铺、需求未至”。已部署的一侧是共享支付令牌、机器支付协议与流式支付；没有发生的一侧是她明确陈述的代理对代理交易量。启动条件在消费者信任的重复次数，以及企业愿意把自助通路对代理开放的意愿上。

报告说商业模式定型那条时间线最慢，这期指出了慢的机制：它被两次重设，一次由推理边际成本重设，一次由代理买家的计费频率重设。报告的成本比价框架里没有给这两笔账定价。

需要给报告加两项扣项。一是推理边际成本让应用层的毛利结构与 SaaS 不同类，二是 token 盗窃这个漏损，两者都会压低报告所说的应用层收入捕获比例。报告里未就绪的项目在这期也得到确认：结果判定与承保在这套支付栈里既无产品也无标准，责任分配规则她没有给。
