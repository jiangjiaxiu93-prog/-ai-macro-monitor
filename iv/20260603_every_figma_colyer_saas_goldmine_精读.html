Figma 的 Colyer 反驳 SaaS 末日论：开发者从数千万到十亿意味着软件总量爆炸，自建代理两年后反而买了更多软件，设计系统与上下文是应用层的价值所在（Every，2026-06-03）

Every · 33 分钟 · 2026-06-03

嘉宾为 Figma 面向开发者的产品管理总监 Matt Colyer，主持人为 Every 的 Dan Shipper（节目 AI & I）。本期是 SaaS 在位者一方对“SaaS 末日论”（SaaSpocalypse）的正面回应，有两点值得单独读：一是他的反驳建立在自己两年自建代理的经历上，论证链完整，落点是“买的软件比以往更多”；二是他把 Figma 这类应用层公司的价值来源拆成了设计系统、上下文、集成与评审四件具体的东西，落在产品层面，比“护城河”这类抽象说法更便于核验。Shipper 自述在录制前约两个月买入了 Figma 股票，对话立场偏向在位者。全片观点属嘉宾判断，数字均为口播，引用前需回原始口径核对。

一、开发者从数千万到十亿：SaaS 末日论的反面是软件总量爆炸

Colyer 的第一层反驳从需求总量入手。他在开发者工具行业工作多年，“五到十年前，全球开发者数量的估计大致是 2500 万、3000 万、4000 万上下；这一次让我兴奋的是，我认为这个数字会变成十亿，甚至更多。” 这段话的口径是他本人口播的行业估计，未引具体来源。他把当下定义为产品开发的民主化时期，围绕“自制软件”（homegrown software）有很多口号，但最终结果只有一个：世界上的软件会比以前多得多。

由此得出他对在位者处境的判断：如果你本来就在这个领域里，“这意味着它是一座金矿”，Figma 与很多 SaaS 公司都是这样看的。这里的推理是软件总量扩张带来的是设计、开发、集成这些配套需求的同步扩张，做设计工具的公司处在扩张的上游（作者归纳）。

他同时承认网上负面情绪的来源，即“如果我可以把每个应用都 vibe code 出来呢”。他注意到一个时间点：2026 年 1 月是“自己造一切”变成主流叙事的月份，而他本人做这件事已经有 18 个月到两年，在他看来是全世界在 1 月追上了他两年前的状态。他对这一波的态度是欢迎，理由在下一节。

二、自建代理两年的教训：软件公司交付的是持续运行，代码只占一部分

第二层反驳是亲身经历。两年前他做的第一个代理是邮件代理，起点是家庭需求：三个孩子在三所学校，家长会邮件每天约 15 封，漏看一封“疯狂发型日”就意味着做家长失败。第一版“实际上就是一个糟糕的 Python 脚本”，抓收件箱顶部的邮件，原样贴给某个大模型，把回复倒回来，提示词只有一句“提取事实”，几页长的邮件回来三条要点。之后加了记忆系统，他称之为“彻底的解锁”，再之后加了每天定时发摘要邮件的主动推送，“不用去工具里问，它自己出现”。他至今不让代理代他回复，仍然是人工审批。

这段经历给出的结论可以直接引用：“软件公司做的东西远不只是代码。我付钱用 Gmail 是有原因的——当 SMTP 版本需要升级时，你只想说我不在乎，我只想收到邮件。” 自己运行代理意味着承担持续的运维成本，“我想要的产品不存在，我把它造了出来，然后我就得到了它的持续成本”。他随后给出反直觉的结果：“说实话，我现在买的软件比以前任何时候都多，因为我会想，那个工具看起来不错，我干脆付钱让别人替我运行代理。”

Shipper 从使用者一侧补了同一个论点：他 vibe code 过不少工具，其中一些发布到了生产环境，“告诉你，这远没有说一句‘修这个 bug’那么简单”，而这一点在 SaaS 末日论的讨论里恰恰被忽略。两人达成的共识可以概括为：让一件 SaaS 软件一直可靠运行是巨大的工程，只有一部分人愿意自己做，其他人愿意付费（作者归纳）。

Colyer 顺带描述了他当前未解决的问题：工作场景里的摘要与过滤。“工作的一部分是理解海量信息，再决定怎么过滤”，难点是有些信息第一遍看起来无关，三天后突然变得重要，如何向代理描述“什么重要什么不重要”至今没有好办法。Shipper 的体验相同：让 Codex 读公司在 Notion 里的全部会议纪要，反馈“不太对”之后代理会过度纠正，把所有要求的东西过于字面地全部塞回来，“从来没有恰到好处”。

三、Figma 的价值来源：设计系统即个性化，MCP 让代码与设计双向闭环

被问到“做内部代理学到了什么”时，Colyer 的回答直接指向应用层价值的落点。“上下文与个性化很重要。在我过去做过的 AI 公司里，个性化往往是排在最后的事，先让它对所有人可用。但把一个还行的代理和一个人们真正喜欢的代理区分开的，是个性化。” 第三方聊天代理里个性化的形式是记忆，Figma 的对应物是设计系统：没有“我们如何组织和拼装设计”这层概念，代理生成的设计从可用性上说就是不能用的。 这也解释了为什么设计工具在位者手里的数据有价值——设计系统本身是企业沉淀在工具里的结构化知识（作者归纳）。

对外部代理与自建代理的取舍，他的答案是两者都要。设计工作流与工程工作流不同，但边界在模糊，“未来我们都会是构建者，区别只是从哪个角度切入问题”。对第三方代理的接口是 Figma 的 MCP 服务器，好处是跨工具的标准接口。他把工作流拆成两个方向。

代码到设计：典型场景是周一早上登录，任务是给注册页加一个 GDPR 复选框，“大多数人不会想‘我应该从一张白纸开始重新想象注册流程’，大多数人只想把活干完”。用户在 Codex、Claude、Windsurf 或 Cursor 里打开代码库，启动 MCP 服务器，让代理启动开发服务器、打开那个页面并复制到 Figma 画布，“它真的会做，这是我们今年早些时候发布的功能之一”，然后用大多数人熟悉的直接操作工具精确调整。

设计到代码：工具名为 Get Design Context，把 Figma 设计里用到的属性、组件以及设计库里的指南打包提供给代理，代理查看代码库、开分支、建 PR、做修改，还可以让它截图贴到 PR 上。人的角色是“你不合并它，但你有了一个好的起点”，与 Shipper 邮件工作流里“每一封回复都要人审批”是同一种分工。

四、走出文本框：设计的钻石模型与画布上的发散代理

在设计工具形态上，Colyer 的判断是行业仍处在“文本框统治的宿醉”里，多数人默认用聊天作为生成式 UI 的交互，而现在开始进入第二章。Figma 刚发布的代理直接运行在无限画布上，内部已用了一段时间。他的论证从设计原则出发：LLM 领域很多东西是旧瓶新装，评测对应单元测试，提示词对应用户输入，设计原则同样不变。

核心原则是钻石模型：先发散再收敛。头脑风暴的规则是不打压任何想法，因为那个阶段的目的只是生成想法。他认为新能力里尚未被解锁的一块正是“给发散思维加速”：人容易困在自己的经验里，从固定角度切入问题，同事的价值在于起点不同，创造力来自两个人的对话。文本框的问题是线性，“这个，然后那个，然后这个”。画布上的代理可以做发散：一帧试灰度，另一帧试棕褐色，棕褐色不错但字体不对，再复制一帧改字体，无障碍不达标再复制一帧。

他把未来分成两类代理。发散代理主动往画布上扔一堆帧，任务是“推它们，试不同方向，别只是加倍下注”。收敛代理面对画布上 25 个营销页概念，把相似的聚成簇，再被要求给出意见，“假装你是一个点进来的客户，哪个最说得通”。“连命令行代理里的佼佼者也做不了这些工作流，这就是我看到的设计与产品思维的未来。” Shipper 的观察是当前代理擅长的是“我已有设计系统，给我第 n 个落地页”这类收敛任务，设计师本来也不想做这类重复工作，发散能力仍待验证。

五、Figma 内部怎么用代理：每个问题都变成上下文问题

Colyer 2026 年 1 月加入 Figma，自称此后几个月内部工作方式的变化“像白天和黑夜”，工程部门照例走在前面。他举的例子来自产品部门的一次 offsite：产品运营团队搭了一套叫 PMOS 的东西。背后的认识是“AI 带来的一个解锁是你会意识到每个问题都变成了上下文问题，工作变成了用正确的信息集合去框定问题。” 产品经理的很多工作对象本来就是结构化数据，于是把组织架构表放进一张 SQLite 表、放到文件系统里，再接上 Asana、Slack、GitHub 等连接器，然后用当时刚流行起来的 skills 把工作流固化。

他喜欢的一个 skill 是新成员入职文件生成。以前经理要手工整理该知道的频道、该认识的人，这些知识“我以前会说完全在我脑子里”。而当上下文被正确组织之后，这些数据其实早就在那里：代理沿组织架构找出新团队的产品、工程、设计三人组，进 Slack 判断这个团队大概是哪三个频道并读最近 30 天内容，再查 Asana 找出全部项目，回来的结果“好得有点不可思议”。

Shipper 用同一逻辑解释为什么 Claude Code 这类本地代理体验突出：大家最初都想做住在云端、永远在线的代理，结果需要手工把它接到所有东西上，而本地代理“就在你的电脑上，你能访问什么它就能访问什么”，能力由此完全不同。他的例子是当天发了一篇文章，问代理该发给谁，代理翻了他的邮件和短信，找出五个他本来会忘掉的人。两人都认为模型能力早就够用，缺的一直是把上下文接起来的“线束与形态”（Shipper 原话为 harness and form factor）。

由此引出对上下文所有权的判断。Colyer 把 Apple 称为“上下文之王”，即便在 AI 上迟到，手机生态握有全部个人数据；他对上一次 WWDC 的 Apple Intelligence 表示失望，仍在等“后台常驻、真正聪明的 Siri”。Google 在他看来也醒过来了，数据未必有 Apple 多但足够多，正在把 AI 产品与自有内容打通，他提到一个据称能自动连接全部 Google 内容的常驻代理产品（字幕拼作 Spark，待核）。Shipper 补充 OpenClaw 走红后人们纷纷买 Mac mini 的现象，认为 Apple 不必参加 AI 竞赛也能靠“所有人都在它的硬件上跑 AI”默认获胜。

六、下一个瓶颈是评审，而 PM 的基本功仍然重要

被问到未来一年的规划，Colyer 的答案只有一个词：评审。“代理有能力生产所有这些东西，足够可得，足够便宜，现在我们被淹没在全新的内容里。” 以前是摘要，现在是净新增的产出在问“要不要我去做”，人成为瓶颈——“我们只有这么多双人眼来评审所有工作”。要解决的是如何把团队的价值体系规模化，让评价这件新东西的标准可以扩展，并建立足够的信任让代理在一定程度上进入自动模式。具体形态他坦言行业和客户都在同时摸索：是录制的视频演示、截图，还是另一个带不同提示词的评审代理，“很难预测，尤其是现在”。

关于产品经理这个职业是否还有未来，他的回答是基础仍然重要。类比是学校里有计算器，但所有人仍然学长除法、学积分与求导，“我现在每天做这些吗，绝对不做，但要驾驭这些系统，理解这些概念并能手工做出来极其重要”。他设想 CS 101 会分裂成两个平行世界：一个是把题目扔进 ChatGPT 直接拿冒泡排序，“42 种写法要哪一种”；另一个是自己用 C 写完，再让模型翻成汇编逐行讲解，顺便解释寄存器与 L1、L2 缓存。“不能用好这些工具的人，是那些只接受输出的人；能发明下一代工具、把工具用到极限的人，是那些追问它怎么拼起来的人。” 他给出的筛选标准是好奇心，并以《银河系漫游指南》里的“那本书”作比，称自己坐飞机时会下载一个小模型离线运行，随便问天空为什么是蓝的。
