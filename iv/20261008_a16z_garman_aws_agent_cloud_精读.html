代理云的基础设施需求、算力供给与企业采用——AWS首席执行官Matt Garman访谈要点梳理（a16z，2026-10-08）

a16z，56 分钟 · 2026-10-08 · 原始来源 ↗

——据a16z节目《Building the Cloud for AI Agents | AWS CEO Matt Garman》（2026-10-08）整理

摘要：本文对AWS首席执行官Matt Garman与a16z的Raghu Raghuram对谈中的主要观点进行了梳理汇总。梳理了代理工作负载对云基础设施的要求、算力需求与供应链约束，介绍了AWS自研芯片、模型服务与代理安全的产品安排，最后阐述了企业采用AI所面临的流程和组织问题。Garman表示，Amazon 2026年资本投资规模为2200亿美元，未来几年将采购200万块英伟达GPU；AWS面向企业的前沿部署工程师项目以约45天的共同开发周期帮助客户建立自身能力。

关键词：企业代理；算力采购；AI资本开支；企业采用；代理安全；AWS；Bedrock；Trainium

一、代理工作负载与云产品的调整

（一）初创企业需求与云服务演进

Garman认为，初创企业是观察未来企业技术需求的重要窗口。一是初创企业较早尝试新的技术架构，今天规模较小的客户可能成长为未来的企业客户。二是成熟企业随后也会采用相近的工具与工作方式，服务初创企业有助于提前建设能力。三是AWS自身已有类似经验，据其粗略估计，约30%至40%的收入来自曾经是初创企业的公司。

他表示，AWS需要持续降低开发者开始使用云服务的门槛。一是简化账户开通流程，逐步推出不到30秒即可完成的注册体验。二是围绕代理的使用方式改善接口，使代理能够直接配置、调用和管理服务。三是保持产品反馈与底层基础设施建设的联动，早期需求可以帮助AWS识别后续企业级负载的方向。

（二）低尾延迟与跨服务上下文

Garman指出，代理反复调用工具，基础设施性能会在连续执行中累积影响。一是关注尾延迟，尤其是P999等指标；一次异常缓慢的调用可能延长整个任务。二是提供快速的数据访问能力，代理的任务涉及多次数据库查询与状态读写，单次请求的平均速度不足以反映完整体验。三是贯通业务上下文，代理需要从S3、Aurora等不同服务中取得信息，云平台应降低跨服务协调的复杂度。

据其介绍，AWS通过Bedrock提供模型访问与相关能力，通过AgentCore提供代理运行所需的基础设施。产品建设的重点包括运行环境、工具调用、记忆、身份与权限等环节。Garman认为，客户需要能够把这些组件组合成生产系统，基础设施应支持代理从短时响应走向连续执行。

（三）任务级身份与隔离环境

Garman认为，代理权限应根据具体任务设计。一是设置代理自己的身份，使系统可以识别某项动作由哪个代理发起。二是限定权限范围与有效时间，代理处理某项任务时获得必要的访问能力，任务完成后不继续保留无关权限。三是避免直接复制用户的全部权限，用户能访问的全部资源与代理完成当前工作的必要资源存在差别。

运行环境方面，AWS利用Firecracker微型虚拟机等技术提供隔离。Garman指出，代理可以生成并执行代码，安全边界因此需要同时覆盖代码运行、数据访问和外部工具调用。隔离、身份与访问控制需要共同发挥作用，才能支持企业逐步提高代理的自主程度。

二、算力需求、资本投资与供应链约束

（一）资本投资与需求来源

Garman表示，Amazon 2026年资本投资规模为2200亿美元，未来几年将采购200万块英伟达GPU。前者是Amazon整体资本投资口径，后者是后续数年的采购安排。

对于需求的持续性，他给出三点判断。一是需求覆盖训练、推理以及生产系统所需的存储与计算，客户结构较为分散。二是AWS单一客户的收入占比处于个位数水平，不能仅根据某一家实验室的变化判断全部需求。三是初创企业之间会出现经营分化，但失败公司的应用尝试可能由其他参与者继续推进，个别公司的退出不必然意味着技术需求消失。这是其对需求延续性的判断。

（二）初创企业容量与配置调整

据Garman介绍，AWS为初创企业保留一定的GPU容量，以避免资源完全流向已有大型客户。一是满足新团队的早期研发需求。二是允许客户调整区域、硬件配置或交付时间。三是把短期容量安排与长期采购规划结合，尽量寻找可用的替代方案。

他表示，约60%的相关需求可以通过上述调整得到满足，其中包含延期、变更区域或更换配置等情况。该比例涵盖经过协商的供给安排，并不表示客户都能立即获得最初提出的资源配置。

（三）动态瓶颈与多年建设周期

Garman指出，基础设施扩张的约束会随着建设进程变化。一是芯片与配套部件，包括高带宽内存、晶圆产能、网络设备与固态硬盘。二是数据中心建设，需要协调建筑、设备安装与交付。三是电力供给，发电、输电与配电的建设周期较长，部分约束无法仅靠增加采购金额快速解决。

据其介绍，AWS提前数年开展供应链规划，并持续与供应商协调。Garman认为，某个环节获得缓解后，另一个环节可能成为限制因素，基础设施供给需要按完整系统管理。单独观察GPU数量难以反映最终可交付的算力。

三、自研芯片与模型服务的经济性

（一）Nitro与Graviton的系统优化

Garman介绍了AWS自研硬件的两个方向。一是Nitro，把网络、存储、安全与虚拟化等功能从通用处理器卸载到专用硬件，减少基础设施功能对客户计算资源的占用。二是Graviton，通过自研处理器改善通用计算的性能与价格关系。

据其介绍，Graviton在相关比较中可提供约20%的性能提升与约20%的价格下降；AWS前100家客户中，超过90%在某种工作负载中使用Graviton。这些数字反映其介绍的产品表现与采用范围，具体负载仍需要依据应用需求进行选择。

（二）Trainium与推理成本控制

Garman表示，Trainium3已经进入市场，Trainium4已经宣布、尚未发布；Bedrock相当部分流量运行在Trainium上。AWS同时提供英伟达GPU与自研芯片，让客户根据模型、软件兼容性、成本和供给情况作选择。

他认为，企业可以从三个方面控制模型使用成本。一是选择适合任务的模型，避免全部请求都依赖同一档前沿能力。二是利用开放模型，通过微调、蒸馏等方式适配自身场景。三是结合芯片与服务层优化，提高实际工作负载的执行效率。数据保护是这类部署的前提，客户需要对自身数据的使用范围保持控制。

四、企业代理的生产部署与组织变化

（一）流程重构与生产评估

Garman认为，企业采用代理的阻力同时来自工作流程与信任。一是重新设计流程，仅在原有流程外部添加聊天入口，未必能释放代理的作用。二是建立可靠性评估，企业需要回测任务表现，并观察模型和业务条件变化后的漂移。三是逐步确定自主执行范围，使代理能力与组织愿意承担的风险相匹配。

据其介绍，AWS前沿部署工程师与客户共同开发，以约45天为一个目标周期。项目既要交付可用成果，也要让客户团队学会继续建设与维护，减少长期依赖外部实施人员的情况。

（二）员工工具与小团队试验

Garman表示，Amazon正在推广Quick等AI工具，并尝试调整团队工作方式。一是让员工更方便地获取内部信息、分析资料与完成业务动作。二是探索由较小团队承担完整项目，在部分试验中把约10人的团队调整为3至4人。三是观察代理工具如何改变开发、协调与交付环节，组织设计仍处于试验之中。

总的看，Garman认为，代理带来的需求需要云服务同时改善计算、数据访问、身份权限与运行环境。AWS的建设方向是扩大可交付算力、提供多样化芯片与模型选择，并帮助企业在可信的边界内重构工作流程；企业能否持续使用代理，与基础设施能力及组织自身的部署能力共同相关。
